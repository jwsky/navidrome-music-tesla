# 收藏语义与部署差异

2026-10-10 统一：**Favorite / 最爱 / 收藏 = 当前 Navidrome 用户的歌曲 star 标记**。
入口显示“哄睡最爱”也使用这一机制。改文案不得偷偷改变集合。

| 项目 | GitHub 单文件客户端 | 家庭部署 |
| --- | --- | --- |
| 最爱读取 | `getStarred2.song` | 同一个接口、同一个账号收藏 |
| 加入 / 取消 | `star(id)` / `unstar(id)`，随后 `getSong` 确认 | 受鉴权的私有操作服务调用相同接口并确认 |
| 入口名称 | `favoriteName`，默认“最爱” | “最爱” |
| 账号来源 | 用户在本机设置 | 家庭服务配置 |
| 元数据缓存 | 服务器 + 用户名；不含显示名 | 同样隔离，可附带受登录保护的首次快照 |
| 删除原文件 | 不支持 | 私有服务已有能力，必须另行确认 |
| 外部音源 | 用户自行启用的可选插件 | 家庭自己的搜索后端 |

普通歌单是独立对象；不能把 `updatePlaylist` 当作 Favorite 的实现。改显示名不查同名歌单，
不自动建立 `宝宝哄睡` 或 `Favorites`。心形只对应歌曲，不能把收藏专辑展开进最爱。
单曲意图与歌单意图由语音服务处理，不得从这个入口名称推断播放意图。

旧 `bedName` 设置和旧歌单缓存不能作为新最爱来源。新缓存前缀是 `navidrome-tesla.favorites.v1`。
代码里保留的 `bedtime` 函数名、DOM id 和缓存标签属于兼容名称，不表示数据源仍为普通歌单。
迁移旧歌单只给用户选定的歌曲加 star；不得删除旧歌单、取消已有 stars 或导出个人曲目到仓库。

Navidrome 每个用户只有一份原生歌曲收藏。需要独立集合时使用普通歌单，或另一个账号；
不能声称只改入口名称就能产生独立的“哄睡收藏”。可选的原生智能歌单能用 `loved=true`
显示收藏，见 [Navidrome 文档](https://www.navidrome.org/docs/usage/features/smart-playlists/)。
本客户端直接使用 `getStarred2`，不依赖智能歌单名称或导入。

修改收藏、缓存、账号切换后运行 `node --test tests/*.test.cjs`。测试使用虚拟曲库，不能连接家庭
播放控制接口。必须保留：取消收藏不删文件 / 不中断播放、迟到刷新不撤销新操作、账号切换不串数据。
公开仓库不能包含家庭凭证、固定歌单 ID、初始化私人歌曲快照或私有域名。
