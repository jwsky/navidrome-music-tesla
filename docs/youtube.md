# YouTube 搜索怎么开

默认是关的。不填 key 就完全不启用，一个请求都不会发。

开了之后，搜索结果里会多出带 `YT` 角标的条目，库里没有的歌可以直接点开就放。
播放的是解析出来的音频直链，走的还是播放器自己的 `<audio>`，**不嵌 YouTube 播放器**，
所以进度条、上一首下一首、方向键这些跟本地歌曲的行为完全一样。

## 需要什么

两个跑在 RapidAPI 上的第三方 API，都有免费档：

| API 名称 | 干什么 |
|---|---|
| **yt-api** | 搜索，返回视频列表 |
| **youtube-mp36** | 把某个视频转成可直接播放的音频链接 |

去 RapidAPI 上**按名字搜这两个**订阅即可（这里不放链接，同名的 API 有不少，
自己搜一下认准提供方，也顺便看看当前的免费额度）。

## 步骤

1. 注册一个 RapidAPI 账号
2. 搜 **yt-api**，进去点 **Subscribe to Test**，选免费档（通常叫 Basic）
3. 搜 **youtube-mp36**，同样订阅免费档
4. 在任意一个 API 页面的代码示例里，把 `X-RapidAPI-Key` 那一串复制出来
5. 打开播放器 → 右上角齿轮 → **YouTube 搜索** → 粘贴进去 → 保存

**两个 API 共用同一个 key。** RapidAPI 的 key 是账号级的，不是每个 API 一个，
所以只要填一次；但两个 API 都必须各自订阅过，否则调用会被拒。

## 关于免费额度

免费档有每月请求数和每秒速率的双重上限，具体数字以 RapidAPI 页面上写的为准
（会变）。日常自己听基本够，但如果你搜得比较猛，可能会撞到速率限制。

**key 可以填多个**，用逗号或换行隔开：

```
key-A, key-B
```

每次请求会随机挑一个用。多个 RapidAPI 账号的 key 混着放能把额度摊开。

## 用起来是什么感觉

- 搜索：和本地库一起出结果，本地的先出（不用等网络），YouTube 的随后补进来
- 播放：第一次点某首歌时，转码接口可能先返回「正在处理」，界面会提示
  「YouTube 正在转码，再等等…」，通常几秒钟，之后再点同一首就很快了
- 歌词：YouTube 的条目没有歌词，右边会显示封面和标题

## 出问题了怎么看

界面右上角会弹提示，对着看：

| 提示 | 什么情况 |
|---|---|
| `还没填 RapidAPI key` | 设置里是空的 |
| `RapidAPI 403` | 这个 API 没订阅，或者 key 抄错了。注意两个 API 都要订阅 |
| `RapidAPI 429` | 撞到速率上限了，等一会儿，或者多配几个 key |
| `YouTube 转码太久了，换一条试试` | 转码接口一直在 processing。换个视频，或者过一会儿再点 |
| 搜索没有 YT 结果，但也没报错 | key 是空的，或者搜索词确实没命中 |

## 一点说明

这两个 API 是第三方服务，不归本项目控制，它们随时可能改接口、改价格或者下线。
key 是你自己的，只存在你自己浏览器的 localStorage 里，请求也是浏览器直接发给
RapidAPI 的，不经过任何中间服务器。
